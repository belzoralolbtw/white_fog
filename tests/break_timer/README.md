# tests/break_timer — sandbox этапа 1.3 (ЖИЗНЕННЫЙ ЦИКЛ ТАЙМЕРА РАЗРУШЕНИЯ)

Это **независимый sandbox** для доказательства логики серверно-авторитетного таймера
разрушения (`START` / `STOP` / `ABORT` + серверный tick) до применения в `src/`.

## Что это НЕ доказывает

Это **чистая логика без Minecraft**. Тест НЕ доказывает runtime-поведение игры
(миксины, сетевые пакеты, реальные `BlockState`/`ItemStack`). Для этого нужна сборка
мода и запуск клиента/сервера архитектором.

## Что проверяется

1. земля рукой: медленный серверный таймер, ровно один commit/дроп (коммит БЕЗ `STOP`);
2. преждевременный `STOP`: сессия СОХРАНЯЕТСЯ, commit только по серверному таймеру (не раньше срока);
3. `ABORT` — отмена без commit;
4. смена инструмента, включая data-компоненты (тот же item id, другой Efficiency) — abort;
5. смена измерения — abort;
6. выгрузка чанка — abort;
7. уход из зоны досягаемости — abort;
8. два игрока на один блок — блок меняется максимум один раз, ровно один дроп;
9. защита «ровно один раз» (`commitNow`) — повторный commit подавлен;
10. горячая станция — отказ в старте;
11. печь (не горит): ванильная кирка нельзя, модовое кайло можно; ровно 1 предмет;
12. листва: ровно 0 дропа при ручном разрушении, в т.ч. ножницами (скрытый ванильный дроп запрещён);
13. ванильная кирка не добывает камень;
14. ванильный топор не добывает бревно;
15. кулак не двигает твёрдый блок (+ подсказка);
16. наполненный котёл — отказ до опустошения;
17. creative: таймер 0, но категории/инструменты НЕ обходятся;
18. `STOP` без `START`;
19. повторный `STOP` после commit — без второго дропа;
20. cooldown подсказки при повторных отказах;
21. станция стала наполненной ВО ВРЕМЯ таймера (BlockState не менялся) — abort, содержимое цело;
22. наполненная станция: отказ на START и последний defensive guard в `commitNow`;
23. **клиент ALLOW (regression + swing fix):** ванильное предсказание подавлено, ровно один `START`,
    никаких `STOP` при удержании, без подсказки (серверный таймер доводит сам); при этом
    `continueDestroyBlock` возвращает `true` → ванильный визуал удара (swing + частицы) на каждом
    continue-тике;
24. **клиент DENY:** `START` не отправляется, `continueDestroyBlock` возвращает `false`
    (без свинга/частиц), локальная подсказка с cooldown 20 тиков на причину (в т.ч. `DENY_HOT`/`DENY_FILLED`);
25. **клиент, смена цели/инструмента:** `ABORT` старой сессии + `START` новой (сервер сам
    сессию не пересоздаёт);
26. **клиент UNCLASSIFIED:** ваниль не подавляется, а собственная сессия мода корректно
    закрывается `ABORT`'ом при переходе на непокрытый блок;
27. **клиент visual (swing fix):** ALLOW — визуал удара на всех continue-тиках, mining-пакетов
    по-прежнему ровно один `START`; DENY — ноль визуальных тиков и ноль пакетов; UNCLASSIFIED —
    мод не вмешивается.

> **Regression fix + swing fix (этап 1.3):** `ClientGate` моделирует клиентский гейт предсказания
> (`MultiPlayerGameModeMixin`) — подавление ванильного тела для ВСЕХ контролируемых категорий,
> ручной `START` для `ALLOW` (плюс ванильный визуал удара: `continueDestroyBlock` → `true`),
> локальную подсказку и отсутствие визуала для `DENY_*` без C2S-пакета, ванильное поведение для
> `UNCLASSIFIED`. Это по-прежнему **чистая логика без Minecraft** (пакеты/`BlockPos`/`ItemStack`
> не проверяются).

## Утверждённые значения (синхронизированы с WhiteFogConfig этапа 1.3)

`RoadmapPolicy` содержит те же длительности и item id, что и `src` (мягкое 40, земля/песок/гравий
рукой 60 и лопатой 10, лёд 80, станция 40, твёрдое модовым кайлом 120/80/40 по tier,
подсказка 20). Модовые id: `white_fog:bronze_pickaxe`/`iron_pickaxe`/`steel_pickaxe`; сами предметы
регистрируются на этапе 6.4 (до этого добыча твёрдых блоков/станций недоступна).

> **Runtime-нюанс 26.2:** ванильный клиент завершает СВОЙ прогресс раньше серверного таймера и
> присылает `STOP_DESTROY_BLOCK`; сервер в `ServerGamePacketListenerImpl#handlePlayerAction`
> всегда подтверждает последовательность (`ackBlockChangesUpTo`). Поэтому и в `src`, и в sandbox
> преждевременный `STOP` НЕ отменяет сессию (нельзя коммитить раньше срока) — отмена идёт по
> `ABORT`/смене блока/инструмента/дистанции/измерения/наполненности.
> **После regression fix'а** контролируемые блоки (`classify != UNCLASSIFIED`) ванильного
> `STOP`/прогресса на клиенте больше не дают вовсе (см. сценарии 23–27). Нюанс остаётся
> актуальным для `UNCLASSIFIED` (обычная ваниль) и для некорректных/устаревших клиентов.
> **Swing fix:** для `ALLOW` `continueDestroyBlock` возвращает `true` — это НЕ возврат ванильного
> тела/таймера, а лишь разрешение вызывающему `Minecraft#continueAttack` выполнить ванильную
> пост-обработку (`addBreakingBlockEffect` + `player.swing`). Ванильный `ServerboundSwingPacket`
> (стандартная cadence майнинга) при этом уходит на сервер, но mining-пакетов `START`/`STOP` нет.
>
> **Динамическая наполненность:** содержимое печи можно добавить за время таймера без смены
> `BlockState` (`LIT=false`), поэтому наполненность проверяется на каждом tick/STOP/commit
> (`BlockBreakRules#isFilled`), а не только при старте; `StationRemoval.commit` — последний
> defensive guard до `removeBlockEntity`.

## Запуск (foreground, само-завершение)

Из корня проекта:

```
tests\break_timer\run_break_timer_selftest.bat
```

`.bat` компилирует только `tests/break_timer/src` во временный `tests/break_timer/build`
(в `.gitignore` через `build/`), запускает `SelfTest` в foreground и пишет UTF-8 лог
в `logs\break_timer_selftest_<stamp>.txt` + `status=SUCCESS|TIMEOUT|FAILURE` в
`logs\break_timer_selftest_<stamp>.result`. Не затрагивает `build.gradle`, `src/`, ресурсы.
