# ROADMAP_STEPS.md — «Белая Мгла»

Каждый тикет является автономным. Кодеру передаётся только один выбранный тикет. Внутри тикета повторены все значения, рецепты, ID и проверки, необходимые для его реализации.

## Обязательный технический контракт версии

- Единственная целевая версия: **Minecraft 26.2**, Fabric Loader/API для 26.2. Stonecutter, версии 26.1.2 и 26.3, NeoForge и Forge не используются.
- Использовать деобфусцированные имена Minecraft 26.2. Не добавлять mappings line, предназначенную для обфусцированных версий.
- Common-код не импортирует `net.minecraft.client.*`. Клиентские классы находятся только в client source set/initializer.
- Для идентификаторов использовать `net.minecraft.resources.Identifier`, для векторов `net.minecraft.world.phys.Vec3`, для типов сущностей — API Minecraft 26.2 (`net.minecraft.world.entity.EntityTypes` там, где требуется тип сущности).
- Для C2S/S2C регистрировать custom payload type один раз в common initializer до регистрации receiver: `PayloadTypeRegistry.serverboundPlay()` для C2S и `PayloadTypeRegistry.clientboundPlay()` для S2C. Регистрация receiver без предварительно зарегистрированного payload запрещена.
- Для HUD использовать client API Minecraft 26.2 с Fabric `HudElementRegistry`/`HudElement`; common gameplay code не должен ссылаться на `GuiGraphicsExtractor`.
- Для клавиш не использовать `org.lwjgl.glfw.GLFW`; использовать `com.mojang.blaze3d.platform.InputConstants`.
- Для сохранения использовать серверный persistent state или компонент игрока с сериализацией в NBT/Codec; состояние обязано переживать save/load, unload/load чанка, disconnect/reconnect.
- Все проверки ресурсов, таймеров, дистанций, урона, крафта и движения выполняются на сервере. Клиентский GUI только отображает состояние и отправляет запрос действия.
- `1 игровой день = 24000 тиков`, `20 тиков = 1 секунда`. Если требуется реальное время, значение указывается отдельно; игровые длительности не смешивать с реальными.
- Любой длительный процесс хранит `startedAt`, `lastProcessedAt`, `duration`, `state`, входы и выход. При загрузке обрабатывать только интервал между фактическими игровыми timestamp.
- Любое списание ресурсов выполняется атомарно после серверной проверки всех входов. Нельзя списывать часть рецепта до подтверждения возможности завершить действие.
- Для каждого изменения использовать проверку сборки и запуск целевого Gradle-задачи для 26.2; кодер не должен добавлять API из других версий Minecraft.

### Этап 1.4: Плоский камень и камушки
- **Новая обязательная спецификация (заменяет прежнее переиспользование stone_slab):** зарегистрировать блок и BlockItem `white_fog:flat_stone` («Плоский камень» / «Flat Stone»), блок и BlockItem `white_fog:small_stone` («Камушка» / «Small Stone»). Установленные камушки — обычные собственные блоки, не decor entity. Стек камушек используется напрямую в рецептах. Vanilla `minecraft:stone_slab` остаётся строительной плитой и больше не открывает станцию.
- **Плоский камень — паспорт:** stack 16, масса 3.0 кг, без прочности; непрозрачная каменная текстура серо-синего оттенка со светлой рабочей поверхностью и сколами. Модель из 3–5 прямоугольных элементов: основание в пределах x/z 1…15, y 0…3 из 16, второй слой x/z 2…14, y 3…4. Не копировать модель vanilla slab высотой полблока. Collision/selection shape — единая коробка x/z 1…15, y 0…4. Поворот horizontal facing меняет ориентацию сколов, но не рецепт; waterlogging не поддерживается, в жидкости установка запрещена.
- **Камушка — паспорт:** stack 64, масса 0.2 кг, без прочности; приземистый неровный камень, два варианта block model со сдвинутыми выступами, текстура общая. Selection box x/z 5…11, y 0…3; collision пустая, игрок не спотыкается. Один блок соответствует одной камушке, количества внутри блока нет. Вариант внешнего вида определяется при установке/генерации и не меняет loot. Не заводить отдельный small_stone_decor entity ID.
- **Файлы и ответственность:** запланировать `FlatStoneBlock`, `FlatStoneBlockEntity`, `SmallStoneBlock`, регистрацию в общих реестрах items/blocks/block entities, `FlatStoneMenu` и клиентский `FlatStoneScreen`. Имена пакетов адаптировать к проекту. Block entity есть только у станции: schemaVersion, owner активного job, входной escrow, progress, output, режим `CRAFT/FORGE`, revision. Пустая станция не хранит данные игрока. Обе модели/предметные definitions и block loot создаются в этом этапе по контракту ресурсов выше.
- **Установка:** ПКМ предметом по верхней стороне полной твёрдой опоры, свободная заменяемая позиция над ней, отсутствие жидкости и прав запрета. Сервер сначала проверяет место, затем ставит один блок и списывает один предмет; creative не списывает. Камушку можно поставить обратно. При удалении опоры блок снимается с обычным однократным loot. Поршень не перемещает станцию с job.
- **Управление без конфликта:** обычный ПКМ по flat_stone открывает станцию; Shift+ПКМ пустой главной рукой снимает только пустую и неработающую станцию. Снятие за один interaction, без таймера. Занятая отвечает «Сначала забери материалы и результат». Камушка подбирается обычным ПКМ любой рукой, но обрабатывается только main-hand event; предмет в руке не расходуется. ЛКМ камушки также выдаёт ровно одну камушку, чтобы случайный удар не уничтожил ресурс.
- **Однократность:** проверка ожидаемого block state и revision, удаление блока и создание единственного результата на серверном потоке. Inventory insert, остаток — обычный ItemEntity в центре бывшего блока с pickup delay 10 тиков. Для interaction-pickup подавить block loot; для обычного разрушения использовать block loot и не вызывать pickup. При взрыве/потере опоры вернуть один block item; contents станции отдельно только из escrow/output. Никакого второго loot на remove callback.
- **Получение:** worldgen этапа 2.1 размещает одну flat_stone рядом с укрытием и минимум 24 камушки в радиусе 32 блоков на доступной поверхности. Резервный рецепт `white_fog:flat_stone_recovery`: Shift+ПКМ крупным `minecraft:cobblestone` по твёрдой земле, второй cobblestone в инвентаре; 2 cobblestone -> 1 поставленный flat_stone за 100 тиков. Это world interaction, не крафт на бегу; движение/урон отменяют с возвратом. До получения крупных камней запасную flat_stone гарантировать в первой руине.
- **Приёмка отдельно:** установить/снять каждый объект 100 раз — количество постоянно; два игрока кликают одновременно — один результат; полный инвентарь — один дроп; unsupported placement не списывает предмет. Vanilla slab не открывает GUI. Проверить границу чанков, взрыв, piston, hopper/меню, save/load с job, отключённые client resources на dedicated server. В этом этапе реализовать пустое меню с вкладкой рецептов; рецепты инструментов добавляются в 3.5.
- **Замена ссылок в дальнейших тикетах:** любое прежнее выражение «поставленная minecraft:stone_slab», «плита», «slab station» в смысле ремесленной станции означает `white_fog:flat_stone`; vanilla slab не является совместимым альтернативным входом. Прежние абзацы ниже описывают старый дизайн и не применяются там, где расходятся с этим паспортом.
- **Цель:** Использовать каменную плиту как переносимую станцию и добавить подбираемые камушки.
- **Входные данные и константы:** Плоский камень: блок/предмет `minecraft:stone_slab`. ПКМ пустой рукой снимает одну плиту как предмет, без инструмента и потери. Поставленная плита снова является станцией. Камушка-декор при ПКМ даёт ровно `1` мелкий камень. Камушка не является обычным ломаемым блоком.
- **Техническая реализация:** На сервере перехватить interaction по `minecraft:stone_slab` при пустой главной руке и только по нужной половине/позиции плиты. Удалить блок и поместить один `minecraft:stone_slab` в инвентарь либо выбросить при полном инвентаре. Создать decor entity/feature камушка с UUID, seed, hitbox и cooldown от двойного клика. Камушка не должен создавать предмет при загрузке чанка повторно; состояние подбора сохранять в entity data. Выдачу делать ровно один раз.
- **Критерий готовности:** Поставить плиту, снять ПКМ, поставить снова и открыть station interaction. Нажать на камушек дважды за один тик — получить только один мелкий камень.
- **Дополнительные требования:** Проверить полный инвентарь, смерть игрока и unload чанка в момент pickup. В каждом случае предмет не должен исчезнуть или появиться дважды.
- **Детализация:** Каменная плита в мире — единственная форма `minecraft:stone_slab`, распознаваемая как плоский камень; тип slab (верхняя/нижняя/двойная) проверяется сервером. ПКМ снимает её только пустой главной рукой, не потребляет durability и сначала пытается положить один предмет в инвентарь, затем создаёт item entity с владельцем и pickup delay. Камушек имеет UUID, `picked=false`, seed и cooldown `2` тика; при полном инвентаре выдача остаётся pending у entity. При unload/load UUID и состояние восстанавливаются, а повторный click после `picked=true` ничего не выдаёт.
