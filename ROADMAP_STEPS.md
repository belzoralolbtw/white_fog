# ROADMAP_STEPS.md — «Белая Мгла»

Каждый тикет является автономным. Кодеру передаётся только один выбранный тикет. Внутри тикета повторены все значения, рецепты, ID и проверки, необходимые для его реализации.

## Обязательный технический контракт версии

- Единственная целевая версия: **Minecraft 26.2**, Fabric Loader/API для 26.2. Stonecutter, версии 26.1.2 и 26.3, NeoForge и Forge не используются.
- Использовать деобфусцированные имена Minecraft 26.2. Не добавлять mappings line, предназначенную для обфусцированных версий.
- Common-код не импортирует `net.minecraft.client.*`. Клиентские классы находятся только в client source set/initializer.
- Для идентификаторов использовать `net.minecraft.resources.Identifier`, для векторов `net.minecraft.world.phys.Vec3`, для типов сущностей — API Minecraft 26.2 (`net.minecraft.world.entity.EntityTypes` там, где требуется тип сущности).
- Для C2S/S2C регистрировать custom payload type один раз в common initializer до регистрации receiver: `PayloadTypeRegistry.serverboundPlay()` для C2S и `PayloadTypeRegistry.clientboundPlay()` для S2C. Регистрация receiver без предварительно зарегистрированного payload запрещена.
- Для HUD использовать client API Minecraft 26.2 с Fabric `HudElementRegistry`/`HudElement`; common gameplay code не должен ссылаться на `GuiGraphicsExtractor`.
- Для клавиш не использовать `org.lwjgl.glfw.GLFW`; использовать `com.mojang.blaze3d.platform.InputConstants`.
- Для сохранения использовать серверный persistent state или компонент игрока с сериализацией в NBT/Codec; состояние обязано переживать save/load, unload/load чанка, disconnect/reconnect.
- Все проверки ресурсов, таймеров, дистанций, урона, крафта и движения выполняются на сервере. Клиентский GUI только отображает состояние и отправляет запрос действия.
- `1 игровой день = 24000 тиков`, `20 тиков = 1 секунда`. Если требуется реальное время, значение указывается отдельно; игровые длительности не смешивать с реальными.
- Любой длительный процесс хранит `startedAt`, `lastProcessedAt`, `duration`, `state`, входы и выход. При загрузке обрабатывать только интервал между фактическими игровыми timestamp.
- Любое списание ресурсов выполняется атомарно после серверной проверки всех входов. Нельзя списывать часть рецепта до подтверждения возможности завершить действие.
- Для каждого изменения использовать проверку сборки и запуск целевого Gradle-задачи для 26.2; кодер не должен добавлять API из других версий Minecraft.

### Этап 1.3: Разрушение блоков и станции
- **Цель:** Задать строгие правила ручного разрушения и контролируемого снятия станций.
- **Входные данные и константы:** Руками медленно разрешены: трава, листва, цветы, саженцы, грибы, `minecraft:snow`, `minecraft:snow_block`, `minecraft:ice`, `minecraft:packed_ice`, `minecraft:blue_ice`, `minecraft:sand`, `minecraft:red_sand`, `minecraft:gravel`, `minecraft:dirt`, `minecraft:coarse_dirt`, `minecraft:rooted_dirt`, `minecraft:clay`. Листва и трава рукой не дают дропа. Земля, песок, гравий рукой медленные, лопатой быстрые. Твёрдые категории: брёвна, доски, камень, руды, кирпич, стекло, металл. Кулак не двигает прогресс твёрдого блока. Сообщение: `Слишком крепко — нужен инструмент`. Деревянные станции `minecraft:crafting_table` и `minecraft:loom` снимаются рукой/топором. `minecraft:furnace`, `minecraft:cauldron`, `minecraft:anvil` снимаются только модовым кайлом. `minecraft:lantern` снимается рукой. Работающая/горячая станция сначала останавливается и остывает.
- **Техническая реализация:** Перехватить начало, прогресс и завершение block break на сервере 26.2. Сервер хранит позицию, UUID игрока, инструмент, стартовый тик и требуемую длительность; клиентский progress bar не является доказательством завершения. Для мягких блоков создать медленный модовый таймер, отменять его при смене блока/предмета/дистанции. Для твёрдых блоков кулаком отменить прогресс и подсказку с cooldown. Vanilla pickaxe не должен добывать камень/руды, vanilla axe — брёвна. Для станций отменить vanilla drop, выдать ровно один блок/предмет, исключить дублирование содержимого и проверить доступность блока в момент завершения.
- **Критерий готовности:** Проверить землю, листву, камень и бревно кулаком. Снять верстак рукой, loom топором, furnace кайлом. Попытаться снять furnace рукой — отказ. Горящая станция не снимается.
- **Дополнительные требования:** Добавить диагностическое логирование причины отказа только в dev-режиме. Проверить break при смене измерения, выгрузке чанка и одновременном клике двух игроков; блок должен измениться максимум один раз.
- **Зафиксированные решения для реализации:**
  - Модовый инструмент называется `white_fog:bronze_pickaxe`, `white_fog:iron_pickaxe` и `white_fog:steel_pickaxe`; первый бронзовый кайло создаётся на каменной наковальне в этапе 6.4. До этапа 6.4 камень и руды не являются обязательным ресурсом для прохождения: доступны стартовые камни, поверхностная медь и болотная руда.
  - Все длительности задаются в игровых тиках, не в реальных секундах: мягкий блок рукой `40` тиков, земля/песок/гравий рукой `60`, лопатой `10`, лёд рукой `80`, модовым кайлом по твёрдому блоку — `40–120` в зависимости от tier. Станция снимается за `40` тиков. Эти значения — конфигурационные, но дефолты обязательны для тестов.
  - Камень, руды, брёвна, доски, кирпич, стекло и металл нельзя завершить рукой или vanilla pickaxe/axe. Vanilla tool может быть использован только там, где явно указан как разрешённый инструмент; отсутствие подходящего tier не повреждает предмет.
  - Листва, `short_grass`, `tall_grass`, цветы, саженцы и грибы при ручном разрушении дают ровно `0` дропа. Дроп с листвы разрешён только отдельной ПКМ-механикой этапа 3.1; ножницы и топор не получают скрытый vanilla-дроп.
  - Наполненная ёмкость или станция всегда даёт отказ до опустошения. Содержимое не выбрасывается автоматически и не удаляется. Для `furnace` с `LIT=true`, lit campfire и любой станции с активным heat/fuel таймером добыча запрещена до полного остывания; отдельного cooldown остывания нет — проверяется фактическое состояние `lit/heat`.
  - Горячими считаются furnace/blast furnace/smoker с `LIT=true`, lit campfire и модовые heat states с `heat > 0`. `cauldron` с водой считается наполненным, но не горячим; его можно снять только после опустошения.
  - Cooldown отказа для сообщения `Слишком крепко — нужен инструмент` равен `20` тикам на игрока и причину. Сообщение не отправляется каждый тик и не создаёт break-progress.
  - Creative не обходит серверные категории, дистанцию, горячие/наполненные станции и запрет vanilla tools. В creative таймер равен `0`, durability не расходуется, но все остальные проверки и однократность commit сохраняются.
  - Дальность проверяется через vanilla `isWithinBlockInteractionRange(pos, 1.0)` на сервере при старте и каждом обновлении; при смене измерения, unload чанка, смерти, disconnect, смене блока или предмета сессия отменяется без дропа.
  - Commit выполняется под серверной защитой позиции: повторный packet, второй игрок и второй обработчик видят уже изменённый блок и не выдают второй предмет. Для обычных блоков используется vanilla loot только после проверки категории; для станций сначала удаляется блок, затем атомарно выдаётся ровно один блок, а пустое содержимое возвращается отдельными слотами.
